# v0.0.54 — release preparation

Intended next patch release; the release workflow determines the version from published tags. Repository manifests remain at the current source version until that workflow prepares its release commit.

## Changes

- Dictation processing now belongs to one native session. Settings are captured at recording start, and observing a completed result cannot repeat paste.
- Save the original transcript before cleanup and delivery. If saving fails, return the text for copying and skip automatic paste.
- Validate cleanup and dictionary proposals for supported protected details. Keep the original when a check fails.
- Distinguish confirmed insertion, unconfirmed paste and failed delivery in History. Uncertain paste is never retried automatically.
- Include audio finalization and observed insertion in native timing. Serialize clipboard restoration with new publications to prevent stale restore timers from interfering with a subsequent dictation.

## Measured result

Speech error counts are unchanged on the repeated 30-clip comparison. Cleanup blocks the known incorrect rupee amount and a dropped name, but also rejects one valid time-formatting edit: reference matches change from 25/38 to 24/38. Timing variation does not establish a speed improvement. See the [full comparison and evidence](../benchmarks/native-pipeline-2026-09-19.md).

## Acceptance

Automated checks and packaged-app acceptance are recorded in the PR. Before publishing, confirm real recording/paste from the Finder-launched candidate and verify clipboard preservation in supported destination apps. Browser mocks alone do not cover macOS permissions or cross-application insertion.

Cleanup remains opt-in. Preservation checks are conservative and incomplete; unverified delivery can still have inserted successfully. Check the destination before manually retrying.
